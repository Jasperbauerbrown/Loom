Spawn a thread: a separate conversation with its own context that works toward one goal in parallel while you stay available. Use it for work of more than about five tool calls — a survey, an investigation, a build, a summary across many files — even when what comes back is short, and for anything that will produce files or be returned to later. Give it what it needs and nothing more: a clear goal, the relevant excerpt of what was said (not your whole conversation), and the notes you already checked, pinned so they are in its context every turn. Arguments: `goal` (required, one paragraph: the outcome — for an investigation, the notes it must write and where — constraints, how to verify); `excerpt` (text from this conversation the thread needs verbatim: the request, decisions, constraints); `notes` (vault paths to pin for the thread, e.g. ["projects/music-bot.md", "devices/ender-3.md"]; each must exist); `roots` (extra filesystem roots the thread may use, such as the folder it will work in); `preset` (a model preset name to run the thread on; omit for the worker role's default, which suits most threads — for a long-horizon or hard-reasoning goal, or bulk mechanical work where speed matters more than depth, run `presets_list` to list valid names and what each is for, and pass the one that fits); `title` (a short label for lists and notifications; give one — the default is the goal's first sentence, cut to 80 characters); `isolation` ("worktree" when the thread will change a git repository: it gets its own checkout of that repository on branch `loom/<thread id>`, which replaces the repository in its roots, so its work cannot touch the live checkout or any sibling thread's, and the branch is how it comes back — omit it otherwise); `isolation_root` (which of `roots` the worktree is made from; the first root by default). Returns the new conversation id. The thread keeps its status in its own transcript and files its walkthrough in the daily log; it reports back to you when it stops without finishing, is blocked, or finishes. A thread may spawn sub-threads of its own within the depth limit, each with its own goal.
