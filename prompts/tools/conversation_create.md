Spawn a thread: a separate conversation with its own context that works toward one goal in parallel while you stay available. Use it when work will take many steps, will produce files, or the person will want to continue talking about it later. Give it what it needs and nothing more: a clear goal, the relevant excerpt of what was said (not your whole conversation), and a scope note. Arguments: `goal` (required, one paragraph: outcome, constraints, how to verify); `scope_note` (vault path of the project note, e.g. `projects/music-bot.md`; if the project has no note yet, pass `project_name` instead and one is created under the projects root, with `aliases` — the other names people will use for it, e.g. ["3d map", "map project"] — so later requests resolve to it); `excerpt` (text from this conversation the thread needs verbatim: the request, decisions, constraints); `roots` (extra filesystem roots the thread may use); `preset` (a model preset name to run the thread on; omit for the worker role's default); `title` (a short label for lists and notifications; give one — the default is the goal's first sentence, cut to 80 characters). Returns the new conversation id. The thread reports back to you when it needs input, is blocked, or finishes.
